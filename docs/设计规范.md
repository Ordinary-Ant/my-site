# 设计规范

> **这份文档是什么**：本项目**视觉令牌权威来源；一期范围以12、动效数据合同以08为准，用户明确决策优先**。设计图是"长什么样"，设计文档是"为什么这样"，这份规范是"**具体用什么值**"。
>
> **谁该看**：任何新增页面、新增组件、新增动效之前，先看这里。与设计图冲突时以本规范为准，并回头修正设计图。
>
> 版本 v2.0 · 2026-10-07一期合同修订 · 对应设计稿 [design/](../design/README.md) · 动效技术细节见 [08-motion-system.md](08-motion-system.md)

## 1. 设计定位与风格基准

### 1.1 参考作品

| 项 | 值 |
|---|---|
| **参考作品** | [Clay Showreel 2023](https://showreel.design/videos/clay-showreel-2023/) |
| **参考站点** | [clay.global](https://clay.global/) |
| 分类 | UI/UX Motion |
| 风格标签 | **Minimal / Clean** |
| 行业 | Tech & SaaS |
| 出品方 | Clay —— 旧金山 UX 设计与品牌公司，客户含 Slack、Snapchat、Coinbase/Grayscale、STC Bank、Joe & The Juice |

> **诚实说明**：我无法观看视频，也无法观测 clay.global 的实际动画曲线。下面第 1.1 节之后的内容，是从**可查证的元数据**（Minimal/Clean、UI/UX Motion）、**该站点的定位与内容结构**、以及**这一风格类别的通行惯例**推导出来的。
> **请你逐条核对**：凡是标了 `⚠ 待确认` 的，都是我的推断而非观测结果。

### 1.2 风格关键词

```
克制 · 干净 · 大字号 · 大留白 · 有节奏但不喧闹 · 每一处动效都有理由
```

Clean 不等于无聊。Clay 那类作品的观感来自**三件事**：

1. **排版本身就是主角** —— 大号无衬线标题、精准的字距、克制的行高
2. **动效是编排不是装饰** —— 元素按顺序入场、按节奏推进，而不是各自乱动
3. **几乎所有动效都是"进入/离开"** —— 而不是"一直在动"

### 1.3 六条设计原则

| # | 原则 | 具体含义 |
|---|---|---|
| P1 | **内容优先于容器** | 先确定标题的字号与行长，再决定卡片怎么排。不要先画一堆卡片再往里塞字 |
| P2 | **动效只做两件事：引导注意力、解释空间关系** | 做不到这两件事的动效一律删掉 |
| P3 | **首屏不依赖 JS** | 首屏可见内容的动效必须用 CSS 实现，保证 JS 未就绪时也正确渲染 |
| P4 | **一次只动一件事** | 同一个时刻，页面上只允许一个区域在做主要运动 |
| P5 | **缓动永远比时长重要** | 同一段动画，缓动错了就廉价，时长错了只是慢 |
| P6 | **默认静音** | 没有交互、没有进入视口时，页面是**完全静止**的 |

### 1.4 明确「不要什么」

这一节和上面同样重要。以下都是 Minimal/Clean 风格的反面：

| ❌ 不要 | 为什么 | 替代做法 |
|---|---|---|
| 粒子背景、星空、极光 | 属于 "Motion Graphics" 风格，与 Clean 冲突；且最耗电 | 纯色或极淡的单层渐变（且默认关闭） |
| 一直在循环的动画（旋转、呼吸、脉冲） | 违反 P6「默认静音」，分散注意力 | 只在 hover / 进入视口时触发 |
| 弹跳（bounce）、弹性过冲（elastic） | 廉价感的主要来源 | `outExpo` / `outQuint` 类的强减速曲线 |
| 超过 1200ms 的入场动画 | 让人等 | 编排代替时长：多个 600ms 交错，而不是一个 2000ms |
| 元素「飞入」横跨大半个屏幕 | 视觉噪音大 | 位移控制在 12–32px 之间 |
| 同时动 3 个以上区域 | 违反 P4 | 用 `stagger()` 排成序列 |
| 渐变文字 + 发光 + 阴影叠满 | 与 Clean 冲突 | 只选一个强调手段 |
| 鼠标跟随光晕 | 属于炫技向 | 一期不实现 |

## 3. 动效系统（一期version2）
完整合同/默认值/升级/API以[08](08-motion-system.md)为准，与src/config/motion.ts同步。仅static/editorial/narrative/kinetic，默认editorial、decoration.none；装饰仅none/tint静态底色（opacity0..0.15），不保留连续背景、光标、粒子、视差或磁吸。

CSS首屏Hero标题/副标题/CTA与基本状态；Anime.js仅离屏内容编排。普通后台不加载，预览页按需使用同一运行时。关闭或JS失败内容可读。系统reduce最高优先，移动按mobileIntensity，隐藏暂停/卸载清理，API缺失保守降级。

### 3.1 缓动和时长
| 令牌 | CSS值 | 用途 |
|---|---|---|
| ease-enter | cubic-bezier(0.16,1,0.3,1) | 入场 |
| ease-exit | cubic-bezier(0.4,0,1,1) | 退场 |
| ease-standard | cubic-bezier(0.4,0,0.2,1) | 状态/位置 |
| ease-soft | cubic-bezier(0.25,0.46,0.45,0.94) | 悬停 |

基础状态80/180/280ms；可配置reveal150..800ms，默认450ms，stagger0..100ms默认60ms。首屏CSS必须有关闭/reduce兜底，不用opacity0等待JS解锁。卡片lift最多-4px，链接underline；正文不做首屏入场。无无限循环背景。

### 3.2 验收
四预设、升级、嵌套严格校验、reduce动态变化、移动降档、关闭/失败可读、实例卸载、预览一致；动效≤28KB gzip，文章≤135KB，登录≤110KB。预算必须真实测量，不以估算或Next First Load值替代。

### 4.2 交互状态矩阵（每个可交互组件必须实现全部）

| 状态 | 视觉 | 动效 |
|---|---|---|
| 默认 | 见 §2 令牌 | — |
| **悬停** `:hover` | 背景变 `--bg-muted` 或边框加深 | 180ms `ease-soft` |
| **焦点** `:focus-visible` | `outline: 2px solid var(--ring); outline-offset: 2px` | **立即，无动效** |
| **按下** `:active` | `scale(0.98)` | 80ms |
| **禁用** `disabled` | `opacity: 0.5` + `cursor: not-allowed` | — |
| **加载** | 文字换成骨架或 spinner，宽度不变 | — |
| **错误** | `border-color: --destructive` + 下方红字 | — |

> **焦点态必须与悬停态等效**：键盘用户 Tab 到卡片时，应看到与鼠标悬停相同的视觉反馈。见 [§7 可访问性](#7-可访问性规范)。

### 4.3 触控目标

移动端所有可点击元素 **≥ 44×44px**。不满足时用透明的 `::after` 扩大点击区，**不要**放大视觉尺寸。

```css
.tap-target::after {
  content: ''; position: absolute; inset: -8px;
}
```

## 5. 布局规范

### 5.1 容器

| 容器 | 最大宽度 | 边距（移动 / 桌面） | 用途 |
|---|---|---|---|
| `container-page` | 1200px | 16px / 24px | 列表页、首页、后台 |
| `container-prose` | 720px | 16px / 24px | 文章正文、Hero 文案 |
| 后台主区 | 不限（`flex: 1`） | 16px / 24px | 表格类页面例外，可以更宽 |

### 5.2 栅格

| 断点 | 网格 |
|---|---|
| 移动 | 常规单列；首页精选作品横向轨道 |
| `sm` 640px | 2 列 |
| `md` 768px | 2 列（作品集/优势）/ 单列（文章） |
| `lg` 1024px | 3 列（作品集）/ 2 列（文章卡片）/ 单列（文章正文） |
| `xl` 1280px | 4 列（首页精选作品） |

**网格间距**：移动 14px，平板 20px，桌面 20px。

### 5.3 三端差异（关键，不是缩放）

| 元素 | 移动 | 平板 | 桌面 |
|---|---|---|---|
| 导航 | 顶部汉堡 + **底部 Tab Bar** | 顶部横向导航 | 顶部横向导航 + 搜索/主题 |
| 时间轴 | **单列右对齐**（不做左右交替） | 单列 | 中轴左右交替 + 年份锚点 |
| 文章详情 | 无 TOC，顶部阅读进度条 | TOC 折叠为抽屉 | 右侧 sticky TOC |
| 作品详情 | 图片置顶，信息堆叠 | 两栏 | 左图右信息 |
| 后台表格 | **转卡片式**（不用横向滚动） | 隐藏次要列 | 完整列 |
| 悬停动效 | 全部禁用（无 hover） | 同桌面 | 启用 |

> **平板不是放大版的手机，也不是缩小版的桌面。** 尤其注意「无 hover」这一点 —— 用 `@media (hover: hover) and (pointer: fine)` 判断能力，而不是用屏幕宽度猜。

## 6. 内容规范

### 6.1 图片

| 用途 | 比例 | 最小宽度 | 格式 |
|---|---|---|---|
| 作品 / 文章封面 | 16:9 | 1200px | AVIF → WebP → 原格式 |
| 日志图集 | 4:3 | 800px | 同上 |
| 头像 | 1:1 | 256px | WebP |
| 分享图 OG | 1.91:1 | 1200×630 | PNG（`next/og` 动态生成） |

**必须写 `alt`**。装饰性图片用 `alt=""`，不要省略。

### 6.2 代码块

- 语言标签显示在左上角，复制按钮在右上角
- 服务端 Shiki 高亮，输出纯 HTML + CSS，**零客户端 JS**（复制按钮是唯一的水合部分）
- 横向滚动，**不换行**
- 暗色主题固定用深色背景（不跟随主题翻转，代码在浅底上更易读）

### 6.3 文案

| 位置 | 规范 |
|---|---|
| 页面标题 | 具体优于抽象。"我为什么选择 Next.js" 而非 "技术分享" |
| 空态 | 说明**为什么空** + **下一步做什么**，不要只写"暂无数据" |
| 错误 | 说人话 + 给出路。"请求超时，可以重试" 而非 "Error 500" |
| 按钮 | 动词开头。"保存"、"新建文章"，不要 "确定" |
| 危险操作 | 明确后果。"移入回收站" 而非 "删除"（可恢复时） |

## 7. 可访问性规范

| 项 | 要求 | 检验方式 |
|---|---|---|
| 色彩对比度 | 正文 ≥ **4.5:1**，大字（≥18.5px 或 14px 粗体）≥ **3:1** | 亮暗两套主题都要测 |
| 焦点可见 | **所有**可交互元素有可见焦点环，禁用 `outline: none` | 只用键盘走一遍全站 |
| 键盘可达 | 无"只能用鼠标"的交互 | 断开鼠标试一次 |
| 跳转链接 | 页面首个可聚焦元素是「跳到主内容」 | Tab 一次即到 |
| 语义标签 | 每页**仅一个 `h1`**；`nav` `main` `article` `aside` `footer` 正确使用 | — |
| 图标按钮 | 必须有 `aria-label` | — |
| 表单 | 每个输入有 `<label>`；错误用 `aria-describedby` 关联 | — |
| 弹窗/抽屉 | focus trap、`Esc` 关闭、关闭后焦点回到触发元素 | — |
| 动效 | 强制尊重 `prefers-reduced-motion`；闪烁 ≤ 3Hz；装饰层 `aria-hidden` | — |
| 内容可见性 | **动效失败时内容必须可见**，绝不出现"永久 opacity:0" | 禁用 JavaScript 后检查 |
| 语言 | `<html lang="zh-CN">` | — |

> **最容易被忽略的一条**：`prefers-reduced-motion` 的优先级**高于后台的任何动效配置**。用户系统里的无障碍偏好，站点无权覆盖。

## 8. 性能预算

### 8.1 体积

| 项 | 预算 | 当前实测 |
|---|---|---|
| 首屏 JS（文章详情） | **≤ 135 KB** gzip | 未实现，待真实gzip测量 |
| 首屏 JS（后台登录页） | ≤ 110 KB gzip | — |
| **动效 JS 合计** | **≤ 28 KB** gzip | Anime.js 24.8 KB + 自研 ~2 KB |
| 后台 JS | 普通页不加载，动效预览页按需加载 | 预览之外只保留CSS状态过渡 |
| 单页图片总重 | 移动 ≤ 800 KB / 桌面 ≤ 1.5 MB | — |
| CSS | ≤ 40 KB gzip | — |

> **预算调整说明**：原定「动效 JS ≤ 25 KB」，实测 Anime.js 完整能力 24.8 KB 已接近上限，加上自研运行时必然超出。因此**放宽到 28 KB**，并把首屏 JS 预算从 110 KB 提到 135 KB。
> **这是接入动画库的必然代价**，用三条措施换回来：
> 1. **普通后台不加载** Anime.js（预览页按需）
> 2. **首屏 Hero 用 CSS**，Anime.js 只接管滚动之后的部分
> 3. **删掉手写 Canvas 粒子**（12 KB），Clean 风格本来也不需要

### 8.2 运行指标

| 指标 | 移动 | 桌面 |
|---|---|---|
| LCP | ≤ 2.0s（4G） | ≤ 1.2s |
| INP | ≤ 150ms | ≤ 100ms |
| CLS | ≤ 0.05 | ≤ 0.05 |
| 动画帧率 | ≥ 50fps | ≥ 58fps |
| Lighthouse Performance | ≥ 85 | ≥ 95 |
| Lighthouse A11y / Best Practices / SEO | ≥ 95 | ≥ 100 |

### 8.3 只允许动的属性

**可以**：`transform`（`translate3d` / `scale`）· `opacity` · `filter`（克制，仅小面积）· `clip-path`（文字遮罩）

**不可以**：`width` · `height` · `top` · `left` · `margin` · `padding` · `border-width`

> 动这些属性会触发 layout，一帧都可能是几十毫秒。**唯一例外**：`createLayout()` 的 FLIP 动画（它就是专门用来做布局变化的，内部已优化）。

### 8.4 `will-change` 的使用

只在动画**即将开始**时加，结束后立即移除。**不要**在 CSS 里静态写 `will-change` —— 那会让元素永久占用一个合成层。

```js
el.style.willChange = 'transform'
animate(el, { ... , onComplete: () => { el.style.willChange = 'auto' } })
```

### 9.2 CSS

- 设计稿里用 `.kebab-case`（`mock.css` 的约定）
- 生产实现用 **Tailwind 原子类优先**，只有真正复用的才抽成 `@layer components` 里的类
- **所有动画写在一个文件**：`src/styles/motion.css`。组件内不写 keyframes

### 9.3 动效命名

```
--duration-{instant|fast|base|slow|reveal|hero|exit}
--ease-{enter|exit|standard|soft|emphasis}
--stagger-{tight|base|loose}
```

Anime.js 的 timeline 用语义化标签：

```js
const tl = createTimeline({ defaults: { ease: 'outExpo' } })
tl.label('hero-in')
  .add('.hero-title', { ... })
  .add('.hero-sub', { ... }, '-=600')
  .label('hero-cta')
```

## 11. 扩展指引

### 加一个新页面

1. 在 [05-frontend-ia.md](05-frontend-ia.md) 的路由表加一行
2. 在 `design/` 加设计稿（照抄现有页面的骨架与 `.spec` 标注条）

6. 回来更新本规范的 §3.9 动效清单（如果引入了新动效）

### 加一个新动效

1. 先问：它引导了什么注意力？解释了什么空间关系？**答不出来就别加**
2. 确定归属层：CSS 还是 Anime.js？（判断标准见 §3.3）
3. 从 §3.1 / §3.1 / §3.1 里选现成的缓动、时长、交错值
4. 加进 §3.9 的清单表
5. 加进 §3 的降级考虑（移动端要不要降级？）
6. 更新 §8.1 的体积预算

### 加一个新颜色

**先问：现有的语义色能不能表达？** 能就别加。
真需要时：加进 §2.1 的表，同步更新 `mock.css` 与 `globals.css` 两处，并检查亮暗两套的对比度。
