重构了首页的动画

首页动画封面 16:9

首页那套动画是一年多前写的，当时图省事直接上了 Framer Motion。功能没问题，但首屏要多下 40KB 的运行时，而且每个卡片的入场都走 JS 计算，低端机上滑动明显掉帧。这个月终于下决心重写。

思路很朴素：能用 CSS 表达的动画，就不要再交给 JS。入场用 @keyframes 配 animation-delay 做错峰，滚动触发的部分交给 scroll-driven animation，只有需要跟随指针的那两个交互保留 JS。

顺手补上的降级

重写的时候才发现，之前那版完全没处理「用户偏好减少动效」这个设置。这既是个可访问性问题，也是个很容易被忽略的细节——系统里关了动画的人，看到满屏飞入的卡片其实挺难受的。补上的写法大概是这样：

css复制
/* 全局兜底：用户要求减少动效时，把所有动画压到最小值 */
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}

/* 只有在允许动效时，才注册入场动画 */
@media (prefers-reduced-motion: no-preference) {
  .card-enter {
    animation: fade-up 420ms cubic-bezier(.22, 1, .36, 1) both;
    animation-delay: calc(var(--i) * 60ms);
  }

  .card-enter:hover {
    transform: translateY(-2px);
  }
}

改完之后首屏 JS 少了 40KB，Lighthouse 的 CLS 从 0.08 掉到 0.01。更有意思的是代码量：从 180 行的动画组件变成 60 行 CSS，而真正需要维护的东西少了一大半。

唯一的遗憾是 Safari 对 scroll-driven animation 的支持还是慢半拍，所以滚动相关的部分我留了一个特性检测的旁路。等它稳定了再删。
