动效分镜表

配套 docs/设计规范.md §3 与 docs/08-motion-system.md。 本页把规范值可视化成可核对的形式：缓动曲线长什么样、时间轴上谁先谁后、体积花在哪里。

⚠
v1.1 两处方向变更（旧版分镜已作废）
1. 技术：动效接入 Anime.js v4.5.0。删除手写 Canvas 粒子、手写 IntersectionObserver、手写 rAF 计数器。
2. 风格：参照 Clay Showreel 2023 / clay.global（标注 Minimal / Clean）。动效主轴从"背景有多花"改为"页面怎么动" —— 极光、光斑、星空、粒子全部降为默认关闭的可选装饰。
Easing

五条缓动曲线（规范值）

缓动永远比时长重要。同一段动画，缓动错了就廉价，时长错了只是慢。 全站只允许用这五条，不要临时写 ease-in-out。

Anime.js 内置同名 ease
ease-enter
cubic-bezier(.16, 1, .3, 1)
Anime.js 'outExpo'
强减速、干净不弹跳。所有入场都用它。
ease-exit
cubic-bezier(.4, 0, 1, 1)
Anime.js 'inQuad'
加速离开，干脆。所有退场用它，且比入场快。
ease-standard
cubic-bezier(.4, 0, .2, 1)
位置 / 尺寸变化
两端对称。用于位移、展开、FLIP 重排。
ease-soft
cubic-bezier(.25, .46, .45, .94)
Anime.js 'outQuad'
比 enter 更柔。悬停、颜色过渡用它。
ease-emphasis 克制使用
cubic-bezier(.34, 1.4, .64, 1) · Anime.js 'outBack(1.4)'

注意曲线越过了终点线（上方虚线）再回落 —— 这就是"过冲"。它带来一点弹性手感， 但也最容易显得廉价。规范限制它只能用于：需要一个轻微强调的单个元素，每页最多一处。

✗ 不要用于：大面积区块入场、列表交错、任何循环动画
Duration

七档时长刻度

单条动画 不超过 900ms，不低于 80ms。需要更长的观感时用编排，不要拉长时间。

duration-instant
80ms 按钮按下、开关翻转
duration-fast
180ms 悬停进入、颜色变化
duration-base
280ms 悬停离开、小范围状态切换、页面切换
duration-slow
480ms 元素入场（单个区块）★ 默认
duration-reveal
720ms 内容块揭示（含遮罩位移）
duration-hero
900ms Hero 单条线（上限）
duration-exit
200ms 退场 —— 一律比入场快
交错也要计预算：项数 × stagger 不应超过 600ms。10 个以上元素时用 stagger-tight (40ms)，或用 from: 'center' 从中间扩散。
Choreography ★

入场编排（Clay 风格的核心）

Clean 风格的动效之所以不廉价，靠的不是单条动画多漂亮，而是多条动画排成了序列。 总时长 1.6s，但任何单条都不超过 900ms。

Text Reveal

逐行遮罩揭示 —— 本风格的签名动作

文字从下方"推出"，遮罩（overflow: hidden）保证它不溢出到上一行。 首屏用 CSS（0 KB、不依赖 JS），滚动后的内容用 Anime.js 的 splitText（能处理动态换行）。

首屏 Hero · CSS 实现 0 KB JS
CSS —— 服务端渲染时直接写 --i:0 / 1 / 2 ⧉ 复制 
/* 遮罩：让文字"从下往上推出"而不溢出上一行 */
.line-mask { display: block; overflow: hidden; }
.line-mask > span {
  display: block;
  transform: translate3d(0, 110%, 0);
  animation: line-up var(--duration-reveal) var(--ease-enter) forwards;
  animation-delay: calc(var(--i) * var(--stagger-loose));
}
@keyframes line-up { to { transform: none; } }
为什么不用 Anime.js 做首屏：它需要下载 → 解析 → 执行 splitText → 才开始动。 慢网络下用户会先看到静止标题，然后它突然跳一下重播 —— 这是最典型的动效事故。 CSS 在 HTML 到达时就已经在播了。
滚动后内容 · Anime.js splitText 22.8 KB 里的核心
用途：文章正文的小节标题、作品亮点列表
渲染模型
RSC 带来的最大变化不是性能，而是心智模型。
Anime.js ⧉ 复制 
import { animate, stagger } from 'animejs'
import { splitText } from 'animejs/text'

const { words } = splitText('.prose h2 + p', { words: true })

animate(words, {
  opacity: [0, 1],
  y: ['0.6em', '0'],
  duration: 480,
  delay: stagger(40),
  ease: 'outExpo',
})
Interaction

交互动效（全部 CSS，0 KB）

全部包在 @media (hover: hover) and (pointer: fine) 里 —— 触屏设备不会出现"粘住的悬停态"。键盘焦点复用同一套样式。

0 KB JS
为什么全部用 CSS：悬停/焦点是"状态 → 样式"的映射，CSS 伪类天然表达，浏览器直接走合成层，不经过 JS 主线程。 用 Anime.js 做悬停反而会增加 INP 风险。
Architecture

CSS 与 Anime.js 的职责划分

判据很简单：能靠"状态选择器 + transition"表达的走 CSS；需要"按时间轴编排多条"或"感知滚动进度"或"拆分文本"的走 Anime.js。

Degradation

六级降级链

第 ① 级的优先级高于后台配置 —— 用户系统里的无障碍偏好，站点无权覆盖。

①
系统「减弱动态效果」 最高优先级
强制关闭全部动效。Anime.js 直接不初始化（useEffect 开头就 return），背景层 display: none。
②
移动端（< 768px）
splitText 逐行揭示降级为整块淡入；位移减半（20px → 10px）；关闭光标 / 视差 / 磁吸。用 createScope 的 mediaQueries 表达，不手写 resize 监听。
③
设备能力检测
hardwareConcurrency ≤ 4 或 deviceMemory ≤ 4 或省流量 → 完全不加载 Anime.js 层，只保留 CSS。
④
FPS 守护
连续 2 秒 < 45fps → 停掉所有 Anime.js 实例，回落到 CSS 层，并写 sessionStorage 记住本次会话。
⑤
省电模式 / 减少透明度偏好
关闭所有 blur 类效果 —— 大面积 filter: blur 是最耗电的。
⑥
页面不可见
visibilitychange: hidden → 逐个 pause() 保存的动画实例。不要用全局 engine.pause()（会影响其他逻辑）。
Anime.js API 速查
animate(targets, params)
单条补间。animate('.card', { opacity:[0,1], y:[20,0] })
createTimeline({ defaults })
时间轴。tl.add(a, p).add(b, p, '-=500') —— 负值表示与上一条重叠
stagger(ms, { from })
交错延迟。写在参数位置：delay: stagger(80)
onScroll({ target, threshold, onEnter })
滚动观察器。每个区块一个，不要用一个观察整页
createScope({ root, mediaQueries })
React 作用域。必须 return () => scope.revert()
splitText(el, { lines, words })
从 'animejs/text' 导入。用于滚动后的内容
createLayout()
FLIP 布局动画。列表重排、弹窗进出。唯一允许动布局属性的场景
最容易被忽略的一条
! 入场动画失败导致内容停在 opacity: 0，整页看上去是空的 —— 这是动效最常见也最致命的故障。

约定：.reveal 默认 opacity: 1；只有在 html[data-js-ready] 存在时才设为 0 并播动画。 外加 @media (scripting: none) 兜底。验收清单里含「禁用 JavaScript 后内容必须完整可见」。
