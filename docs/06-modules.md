## 模块 1 · 日志（Log）

### 1.1 定位

站点里**最有生命力**的模块。它的价值不在于单篇多好，而在于**持续更新的痕迹**本身。所以设计目标是：**让写日志的成本无限接近于零，让浏览日志的人感受到时间在流动。**

三类内容共用一张表，用 `type` 区分：

| 类型 | 用途 | 典型长度 | 前台表现 |
|---|---|---|---|
| `DAILY` 每日随笔 | 今天做了什么、想了什么 | 100–800 字 | 默认，日历上打点 |
| `EVENT` 大事件 | 换工作、上线产品、拿到 offer | 300–1500 字 | 时间轴上加粗标记 |
| `SUMMARY` 总结 | 月度/年度复盘 | 1000–5000 字 | 单独 Tab，可长文 |

### 1.2 数据来源

表：`Log`（见 [02-data-model.md §3](02-data-model.md)）
接口：`GET /api/v1/logs`、`GET /api/v1/logs/:id`、`GET /api/v1/logs/calendar`

### 1.3 关键字段与前台映射

| 字段 | 前台位置 | 缺省时行为 |
|---|---|---|
| `title` | 卡片主标题 | 必填 |
| `logDate` | 左侧大号日期 + 分组年份 | 必填，决定排序 |
| `type` | 类型筛选 Tab | 默认 `DAILY` |
| `summary` | 卡片摘要（2 行截断） | 从 `content` 截取前 120 字 |
| `content` | 详情正文 | 必填 |
| `mood` | emoji 表情 | 不渲染 |
| `weather` | emoji 图标 | 不渲染 |
| `location` | 带定位图标的文字 | 不渲染 |
| `coverImage` | 卡片与详情顶部大图 | 不渲染 |
| `images` | 详情图集（网格） | 不渲染 |
| `isPinned` | 列表顶部固定 + 📌 标记 | 按日期排序 |
| `tags` | 底部标签 | 不渲染 |

**心情枚举 → emoji 映射**

| mood | emoji | 中文 |
|---|---|---|
| `happy` | 😊 | 开心 |
| `excited` | 🤩 | 兴奋 |
| `calm` | 😌 | 平静 |
| `tired` | 😮‍💨 | 疲惫 |
| `down` | 😔 | 低落 |
| `angry` | 😤 | 生气 |

**天气枚举 → emoji**

| weather | emoji | 中文 |
|---|---|---|
| `sunny` | ☀️ | 晴 |
| `cloudy` | ☁️ | 多云 |
| `overcast` | 🌥️ | 阴 |
| `rain` | 🌧️ | 雨 |
| `snow` | ❄️ | 雪 |
| `fog` | 🌫️ | 雾 |

> **枚举存字符串而非枚举类型**：`mood`/`weather` 用 `String` 存储而非 Prisma enum，因为它们是**可选装饰**，将来想加「🎮 打游戏」这种自定义心情时不用改 schema。取值由 Zod 白名单约束。

### 1.4 前台交互

**列表页（`/logs`）**

| 交互 | 行为 |
|---|---|
| 类型筛选 | `[全部] [每日随笔] [大事件] [总结]`，写进 URL `?type=DAILY` |
| 年份筛选 | 下拉，写进 URL `?year=2025` |
| 视图切换 | 列表 / 日历，写进 URL `?view=calendar`，存 `localStorage` 记住偏好 |
| 按月分组 | 同月日志聚合在 `── 2025 年 1 月 ──` 分隔标题下 |
| 分页 | PC 用分页器；移动端用「加载更多」（每页 10 条） |
| 卡片点击 | 整卡可点，进入详情 |
| 置顶 | `isPinned=true` 的永远在最前，带 📌 |

**详情页（`/logs/[id]`）**

| 交互 | 行为 |
|---|---|
| 顶部元信息 | 日期 + 星期 + 心情 + 天气 + 地点，一行横排（移动端换行） |
| 图集 | 点击图片打开 Lightbox，支持左右切换与 `Esc` 关闭 |
| 上下篇 | 按 `logDate` 相邻，显示标题 |
| 复制链接 | 文末按钮，复制当前 URL |
| 返回 | 顶部 `← 返回日志列表`（用 `router.back()` 保留列表滚动位置） |

**日历视图**

| 交互 | 行为 |
|---|---|
| 月份切换 | 左右箭头 + 键盘左右键 |
| 打点 | 有日志的日期显示圆点，多篇显示数字徽章 |
| 点击日期 | 下方预览该日日志标题；点击预览进详情 |
| 空月份 | 当天无日志时下方显示「这天没有记录」 |

### 1.5 后台管理

后台菜单：**内容管理 → 日志**（`/admin/logs`）

| 功能 | 说明 |
|---|---|
| 列表 | 表格 + 日历双视图；默认日历视图（写日志的场景是"补今天/补昨天"） |
| 新建 | 极简表单：标题 + 正文 + 日期 + 心情天气，**3 个必填项**即可提交 |
| 快速记录 | 仪表盘与列表页都有 [ + 记一笔 ] 按钮，打开侧边抽屉，60 秒能写完 |
| 日期默认 | 新建时 `logDate` 默认今天 |
| 状态默认 | 日志默认 `PUBLISHED`（**写日志不该有"发布"心理负担**） |
| 图集 | 支持多图上传与拖拽排序 |
| 补记 | 允许任意修改 `logDate`，用于补写过去的日志 |

**快速记录抽屉**

```
┌────────────────────────────────────┐
│  记一笔                       [×]  │
├────────────────────────────────────┤
│  日期  [ 2025-01-15        ] 📅    │
│  类型  [ 每日随笔 ▾ ]              │
│  心情  😊 😌 😐 😔 😤  （点选）     │
│  天气  ☀️ ☁️ 🌧️ ❄️    （点选）     │
│                                    │
│  标题                              │
│  [ 今天重构了首页动画          ]   │
│                                    │
│  内容                              │
│  [ 把 Framer Motion 换成了…    ]   │
│  [                              ]  │
│                                    │
│  [ 拖入或粘贴图片 ]                │
│                                    │
│         [ 取消 ]   [ 保存 ]        │
└────────────────────────────────────┘
```

### 1.6 开关行为

| 操作 | 效果 |
|---|---|
| `enabled = false` | `/logs*` → 404；首页日志区块消失；列表接口返回空数组；sitemap 移除 |
| `config.types.DAILY = false` | 列表与日历不显示 DAILY 类型；该类型详情页仍可通过直链访问（**不 404**，避免已分享链接失效） |
| `config.home.enabled = false` | 仅首页不显示该区块，`/logs` 照常 |
| `config.home.limit = 3` | 首页日志区块只显示 3 条 |
| `config.defaultView = 'calendar'` | 前台日志页默认打开日历视图 |
| `navVisible = false` | 导航不显示，但 `/logs` 仍可直链访问 |

> **「子类型开关」与「模块开关」的语义差异**：模块开关是"这个栏目不存在了"，子类型开关是"我不想在这个视图里看到这类内容"。因此子类型关闭**不做 404**，只做视图过滤。

### 1.7 边界与异常

| 情况 | 处理 |
|---|---|
| 同一天多篇日志 | 允许，日历上显示数字徽章 |
| 未来日期的日志 | 允许（提前写计划），但 `logDate > 今天` 的默认在前台**不显示**，除非 `isPinned` 或用户开启「显示未来日志」（防调试草稿外泄） |
| 超长日志 | 正文无长度限制；列表摘要固定截断 120 字 |
| 图片失效 | 图集用 `onError` 替换为占位图，不破坏布局 |
| 删除 | 软删除，进回收站，可恢复 |
| 时区 | `logDate` 是 `@db.Date`（无时间），按服务器时区解释；**在 service 层统一用 UTC+8 处理**，避免跨时区显示成前一天 |

### 1.8 未来扩展

- 日志支持「地点地图」：`location` + 经纬度，做足迹地图
- 自动从 Git 提交记录生成草稿（"今天提交了 12 次，改了这些文件"）
- 情绪趋势图：把 `mood` 按月可视化
- 日志串：把多篇日志串成一个系列

### 1.9 验收标准

- [ ] 后台 60 秒内能完成一条日志的记录（从点击「记一笔」到保存成功）
- [ ] 日志按年月正确分组，`logDate` 不出现时区偏移
- [ ] 日历视图正确高亮有日志的日期
- [ ] 关闭模块后 `/logs` 返回 404 且首页区块消失，重新开启后数据完好
- [ ] 移动端能顺畅完成"看图集 → 切换图片 → 返回"
- [ ] 列表页在移动端用「加载更多」而非无限滚动

## 模块 2 · 作品集（Portfolio）

### 2.1 定位

**用于说服别人"我能干活"的地方。** 招聘方和合作方只会在这里停留 30–60 秒，所以首屏必须是**视觉冲击 + 成果量化**，而不是技术流水账。

四类作品，用 `type` 区分：

| 类型 | 内容 | 卡片视觉 |
|---|---|---|
| `GAME` 游戏 | 可以玩的游戏、Demo | 突出"试玩"按钮 |
| `REPO` 代码库 | 开源库、公司项目（脱敏） | 突出 GitHub 链接与 star |
| `SKILL` Skills | 技术能力展示（如"我能从 0 搭一套设计系统"） | 图标代替封面，突出深度 |
| `OTHER` 其他 | 设计稿、写作、演讲、硬件 | 通用样式 |

### 2.2 数据来源

表：`Project`
接口：`GET /api/v1/projects`、`GET /api/v1/projects/:slug`

### 2.3 关键字段与设计意图

| 字段 | 设计意图 |
|---|---|
| `title` / `subtitle` | 标题说"是什么"，副标题说"一句话亮点" |
| `description` | 卡片简介，**必须回答"解决了什么问题"** |
| `highlights` | 成果量化 bullets，前台置顶展示 —— 这是最被阅读的部分 |
| `techStack` | 徽章，让技术栈匹配度一眼可见 |
| `role` | 担任角色，明确"这是我一个人做的还是参与的" |
| `links` | `{ github, demo, video, docs, article }`，按存在渲染按钮 |
| `coverImage` / `gallery` | 视觉证据（截图比描述有说服力 10 倍） |
| `featured` | 首页精选位 |
| `content` | 可空的详情长文（轻量作品直接外链，不写长文） |
| `startDate` / `endDate` | 时间跨度，`endDate` 为空表示进行中 |

**`highlights` 的写作规范**（写进后台的字段提示文案）：

```
✅ 好的写法（有数字、有结果）：
  • 搭建公司级组件库，覆盖 12 条业务线，复用率 78%
  • 首屏 LCP 从 3.2s 优化到 1.1s
  • 独立完成 12 个关卡、3 种敌人 AI

❌ 不好的写法（只是描述做了什么）：
  • 使用了 React 和 TypeScript
  • 负责前端开发
  • 参与需求评审
```

### 2.4 前台交互

**列表页（`/portfolio`）**

| 交互 | 行为 |
|---|---|
| 类型 Tab | `[全部 15] [🎮 游戏 3] [📦 代码库 7] [⚡ Skills 3] [🔧 其他 2]`，数字是实时统计 |
| 视图切换 | 网格（默认）/ 列表（信息密度更高），写进 URL |
| 排序 | 默认 `order ASC` → `startDate DESC`；可切换"最新优先" |
| 悬停 | PC 端卡片上浮 + 封面图轻微放大（`@media (hover: hover)` 内） |
| 外链按钮 | 卡片底部直接给出主要外链（`demo` 优先于 `github`） |
| 技术栈筛选 | 点某个技术徽章 → `?tech=React` 过滤 |

**详情页（`/portfolio/[slug]`）**

| 交互 | 行为 |
|---|---|
| 图片主区 | PC 左图右信息；点击图片开 Lightbox |
| 图集切换 | 缩略图 + 左右箭头（PC）；滑动手势（移动） |
| 外链按钮组 | 按 `links` 存在情况渲染；`demo` 用实心主按钮，其余用描边 |
| 亮点列表 | `highlights` 渲染为带勾选图标的列表，字号略大于正文 |
| 技术栈 | 每个徽章可点，跳到 `?tech=xxx` 的筛选列表 |
| 正文 | `content` 存在才渲染；不存在则整个区块省略 |
| 上下篇 | 按 `order` 相邻 |

**Skills 类型卡片的特殊处理**

它没有"项目"，但有"能力"。所以卡片渲染为：

```
┌────────────────────────────────┐
│         ⚡                      │
│   设计系统建设                  │
│                                │
│   从设计令牌到组件库到文档站，   │
│   完整落地一套可维护的设计系统   │
│                                │
│   代表产出                      │
│   • 组件库 45 个组件            │
│   • 文档站 200+ 页              │
│   • 12 条业务线接入             │
│                                │
│   相关作品 →  [组件库] [CLI工具]│
└────────────────────────────────┘
```

关联作品通过 `content` 中的链接或 `links.article` 表达。

### 2.5 后台管理

| 功能 | 说明 |
|---|---|
| 列表 | 表格视图，支持网格预览切换 |
| 拖拽排序 | `order` 字段拖拽调整；`featured` 单独一列可切换 |
| 封面图裁切 | 上传后可选裁切区域，保证 16:9 统一（用 `react-image-crop` 或 `sharp` 服务端裁） |
| 图集排序 | 多图拖拽排序，第一张自动成为封面（可覆盖） |
| 外链校验 | 填入 URL 时校验可访问性（HEAD 请求，失败仅警告不阻止） |
| 技术栈 | 从历史技术栈中智能补全（下拉 + 自由输入） |
| 预览 | 保存前可预览卡片效果 |

### 2.6 开关行为

| 操作 | 效果 |
|---|---|
| `enabled = false` | `/portfolio*` → 404；首页精选区块消失 |
| `config.types.GAME = false` | 列表不显示游戏；直接访问游戏详情页**仍可打开**（避免分享链接失效） |
| `config.layout = 'list'` | 前台默认用列表布局 |
| `config.showTechStack = false` | 卡片不显示技术栈徽章 |

### 2.7 边界与异常

| 情况 | 处理 |
|---|---|
| 无封面的作品 | 用类型图标 + 渐变背景生成占位封面，**不留白块** |
| `content` 为 null 但有很多 `highlights` | 详情页正常渲染，只是没有长文区块 |
| NDA 项目 | `description` 里写"因保密协议不便展示细节"，`gallery` 留空，`links` 只留公开部分 |
| 外链失效 | 前端不做校验（避免每次渲染发请求）；后台提供"检查所有外链"的批量工具 |
| 图片比例不一 | 封面统一 `aspect-video` + `object-cover`；图集保留原比例但限制最大高度 |
| 数量很少（< 3 个） | 网格自动改为单/双列居中，不留大片空白 |

### 2.8 未来扩展

- 关联文章：作品 ↔ 文章双向引用
- GitHub API 自动同步 star 数与最后提交时间
- 游戏作品内嵌可玩（iframe 或 WebGL canvas 直接跑）

### 2.9 验收标准

- [ ] 新增一个只有外链、没有长文的作品，详情页正常且不出现空区块
- [ ] 首页精选位正确显示 `featured=true` 的作品
- [ ] 类型 Tab 的数字与实际条数一致
- [ ] 移动端图集可滑动切换
- [ ] 关闭 `GAME` 子类型后，列表不显示游戏但直链仍可访问

## 模块 3 · 时间戳（Timeline）

### 3.1 定位

**用一条线讲完你的职业故事。** 它不是简历的复述，而是"选择与结果"的叙事：为什么去这家公司、做成了什么、为什么离开。

关键设计决策（见 [02-data-model.md §2.2](02-data-model.md)）：**「时间戳」与「关于我」的工作经历共用同一份数据**。

### 3.2 数据来源

表：`TimelineItem`
接口：`GET /api/v1/timeline`；「关于我」页面通过 `GET /api/v1/profile` 的 `experience` 字段复用

### 3.3 类型与配色

| 类型 | 中文 | 颜色 | 图标 | 前台位置 |
|---|---|---|---|---|
| `WORK` | 工作 | 蓝 `#3b82f6` | `briefcase` | 时间轴 + 关于我 |
| `EDUCATION` | 教育 | 绿 `#10b981` | `graduation-cap` | 时间轴 + 关于我 |
| `PROJECT` | 项目 | 紫 `#8b5cf6` | `folder-git-2` | 时间轴 |
| `AWARD` | 荣誉 | 金 `#f59e0b` | `trophy` | 时间轴 |
| `MILESTONE` | 里程碑 | 橙 `#f97316` | `flag` | 时间轴 |

### 3.4 关键字段

| 字段 | 说明 |
|---|---|
| `title` | 如「高级前端工程师」 |
| `subtitle` | 如「商业化中台组」 |
| `organization` | 公司/学校/主办方 |
| `location` | 城市 |
| `startDate` / `endDate` | `endDate = null` 表示"至今" |
| `isCurrent` | 前台显示静态高亮圆点 + 置顶 |
| `highlights` | 关键成果 bullets |
| `description` | Markdown 详述（"为什么做这个选择"写这里） |
| `tags` | 技术栈或关键词 |
| `visible` | 是否在时间戳页显示 |
| `showOnAbout` | 是否在关于我页显示 |
| `order` | 同 `startDate` 时的排序权重 |

### 3.5 排序规则（必须在 UI 上说清）

```
1. isCurrent DESC     —— "至今"的条目永远最前
2. startDate DESC     —— 时间倒序（最新的在上）
3. order ASC          —— 同起始时间时按手动权重
4. id ASC             —— 最后的稳定兜底
```

> **注意反向时间轴的选择**：倒序（最新在上）适合求职场景 —— 招聘方最关心你最近在做什么。若想讲成长故事，可在后台配置 `config.direction = 'asc'`。

### 3.6 前台交互

| 交互 | 行为 |
|---|---|
| 类型筛选 | `[全部] [工作] [教育] [项目] [荣誉] [里程碑]`，写进 URL |
| 年份分组 | `════ 2023 ════` 分隔，PC 端右侧年份锚点可快速跳转 |
| 中轴布局 | PC：奇偶左右交替；平板/移动：左侧单线单列 |
| 当前项 | 静态高亮圆点（所有偏好均无循环动画） |
| 展开详情 | `description` 长文默认折叠，点「展开」查看 |
| 卡片点击 | 无独立详情页 —— 内容直接在时间轴上展开（**避免跳转打断叙事流**） |
| 空类型 | 筛选后无结果时显示「该类型暂无记录」+ 重置按钮 |

**为什么没有详情页？** 时间轴的价值在于"一眼看全"。每条都跳转会让叙事断裂。内容多的条目用折叠展开解决。

### 3.7 后台管理

| 功能 | 说明 |
|---|---|
| 列表即排序 | 列表页每行带 `☰` 拖拽手柄，拖拽写 `order` |
| 时间格式化 | 输入框用月份选择器（`2023-03`），不用完整日期选择器 |
| 「至今」开关 | `endDate` 留空 + `isCurrent=true` |
| 双可见性开关 | 列表里两列：`时间戳页` / `关于我页`，各自独立 Switch |
| 类型筛选 | 按类型过滤列表 |
| 快速复制 | 「以此为基础新建」按钮，方便建相似的条目 |

### 3.8 开关行为

| 操作 | 效果 |
|---|---|
| `timeline.enabled = false` | `/timeline` → 404；**同时隐藏「关于我」页的工作经历区块**（数据同源） |
| `timeline.config.types.AWARD = false` | 时间轴不显示荣誉类型 |
| `about.config.sections.experience = false` | 仅在关于我页隐藏经历区块，时间轴页不受影响 |
| 单条 `visible = false` | 该条不在时间轴显示，但可能仍在关于我页显示 |

> **重要**：后台关闭 `timeline` 模块的确认清单里必须明确写出「关于我页面的工作经历区块也会一并隐藏」，否则用户会以为关于我页面坏了。

### 3.9 边界与异常

| 情况 | 处理 |
|---|---|
| 教育经历与工作经历时间重叠（在职读研） | 允许；前台左右交替自然错开，不做冲突检测 |
| 同公司多段经历（离职又回去） | 建两条独立记录，各自有起止时间 |
| 只有年份没有月份 | 允许，日期落库规范化为YYYY-01-01并保存startPrecision=YEAR，前台显示「2023 年」；月份存MONTH，完整日期存DAY |
| 时间区间倒置（end < start） | 后台表单校验阻止，`400 VALIDATION_ERROR` |
| 条目过多（> 30） | 移动端默认折叠「更早的经历」，点击展开 |
| `isCurrent` 有多条 | 允许，但后台给出警告提示（通常只应有一条） |

### 3.10 未来扩展

- 与 Git 提交/GitHub 活跃度结合，自动生成「贡献热力图」区块
- 每条经历关联作品与文章（"在这家公司做的项目"）

### 3.11 验收标准

- [ ] 前台排序正确：isCurrent优先、日期按direction、同日期order升序、id稳定兜底；年/月/日精度不丢失
- [ ] 修改一条时间戳后，「关于我」页的工作经历同步更新（验证单一数据源）
- [ ] 移动端时间轴为单列右对齐（不是左右交替）
- [ ] 关闭 `timeline` 模块后，`/timeline` 404 且关于我页经历区块隐藏
- [ ] 拖拽排序后刷新页面顺序保持

## 模块 4 · 文章（Article）

### 4.1 定位

**面向公众和搜索引擎的长文。** 与日志的核心差异：日志是"给自己留痕"，文章是"给别人交付价值"。因此文章需要**更强的结构（分类/TOC/SEO）**和**更高的完成度标准**。

### 4.2 数据来源

表：`Article`
接口：`GET /api/v1/articles`、`GET /api/v1/articles/:slug`、分类与标签归档

### 4.3 分类与标签的区别（必须想清楚，否则会乱）

| | 分类 `Category` | 标签 `Tag` |
|---|---|---|
| 关系 | **一对多**（一篇文章只属于一个分类） | **多对多**（一篇文章可有多个标签） |
| 数量 | 少而稳定（3–8 个） | 多而自由（几十个） |
| 用途 | 站点信息架构、导航、URL | 内容关联、检索、兴趣聚类 |
| 树形 | 支持父子（技术 → 前端） | 扁平 |
| URL | `/articles/category/tech` | `/articles/tag/nextjs` |

**判断标准**：这个维度会不会出现在导航里？会 → 分类；不会 → 标签。

### 4.4 写作规范（内置到后台的提示）

| 字段 | 规范 |
|---|---|
| `title` | ≤ 60 字，具体优于抽象 |
| `slug` | 小写 + 连字符，**一经发布不再修改**（改 URL 会丢 SEO，必要时靠 301） |
| `summary` | 100–160 字，用于卡片与 SEO description |
| 正文结构 | 至少 3 个 `##` 二级标题（保证有 TOC） |
| `seoTitle` | ≤ 60 字符，留空则用 `title` |
| `seoDescription` | ≤ 160 字符，留空则用 `summary` |
| `coverImage` | 16:9，宽 ≥ 1200px |

### 4.5 前台交互

**列表页（`/articles`）**

| 交互 | 行为 |
|---|---|
| 分类 Tab | 带实时计数；点击进 `/articles/category/:slug` |
| 标签云 | 高频标签平铺，点击进 `/articles/tag/:slug` |
| 排序 | 默认最新；可切"最热"（按 `viewCount`） |
| 置顶 | `isTop=true` 永远在最前，带 📌 |
| 阅读量 | 由 `config.showViewCount` 控制是否显示 |
| 无限滚动 | **不用**。用分页器，保证 SEO 与位置感 |

**详情页（`/articles/[slug]`）**

| 交互 | 行为 |
|---|---|
| TOC | 由 `##`/`###` 生成；PC 右侧 sticky；当前标题高亮（`IntersectionObserver`） |
| 阅读进度 | 顶部 1px 进度条 |
| 代码复制 | 每个代码块右上角按钮 |
| 图片 | 点击 Lightbox；`alt` 缺失时后台已阻止保存 |
| 分享 | 复制链接 / Twitter / 微博 |
| 上下篇 | 同分类下按 `publishedAt` 相邻 |
| 相关文章 | 同分类 + 共享标签数排序，取 3 条 |
| 阅读量 | 进入页面时 `POST /api/v1/views`，**同 session 同文章只计一次**（`sessionStorage` 去重） |
| RSS | 每篇文章自动进 `/rss.xml` |

**阅读量防刷**

```
同 IP + 同 slug：30 分钟内只计一次（共享PostgreSQL窗口记录）
爬虫 UA：不计（匹配常见 bot UA 列表）
Do Not Track 开启：不计
```
浏览量异步累加（不阻塞渲染），失败静默。

### 4.6 后台管理

| 功能 | 说明 |
|---|---|
| 列表 | 表格，列：标题、分类、状态、浏览、发布时间、更新时间 |
| 分状态 Tab | 全部 / 已发布 / 草稿 / 已归档 / 回收站 |
| 批量 | 发布、下架、归档、打标签、删除 |
| 编辑器 | Tiptap 全功能（见 [04-admin-console.md §5](04-admin-console.md)） |
| 自动保存 | 草稿每 60 秒静默保存；停输 3 秒存本地 |
| 字数统计 | 实时显示字数与预计阅读时长（中文 300 字/分钟） |
| slug | 标题变化时自动生成，用户改过后不再覆盖 |
| 预览 | 打开真实前台 URL 预览（草稿用带 token 的预览链接） |
| 定时发布 | `publishedAt` 设为未来时间 → 该时间前前台不可见（靠 ISR 失效触发） |
| SEO 检查 | 保存时给出提示：标题过长、描述缺失、无封面、正文过短、无二级标题 |

**SEO 检查清单输出**

```
⚠ 建议优化：
  · SEO 描述长度 210 字，建议压缩到 160 字以内
  · 正文只有 320 字，可能不值得独立成文
  ✓ 标题长度合适
  ✓ 已设置封面图
  ✓ 有 5 个二级标题，TOC 结构良好
```

### 4.7 开关行为

| 操作 | 效果 |
|---|---|
| `enabled = false` | `/articles*` → 404；首页文章区块消失；**RSS 只输出日志** |
| `config.showToc = false` | 详情页不显示目录 |
| `config.showViewCount = false` | 列表与详情不显示阅读量 |
| `config.relatedCount = 0` | 不显示相关文章 |
| 分类被删除 | 该分类下文章 `categoryId` 置 null（不删文章），归入"未分类" |
| 单篇 `status = DRAFT` | 前台 404（直链也不可见） |

### 4.8 边界与异常

| 情况 | 处理 |
|---|---|
| slug 冲突 | 后台实时校验并建议 `-2` 后缀；接口返回 `409 CONFLICT` |
| 草稿直链访问 | 404；提供`/preview/:token` 预览链接（token有效24h，no-store/noindex，不进入公开搜索/RSS/sitemap） |
| 正文含大量图片 | 图片懒加载 + 模糊占位；首屏外的图片 `loading="lazy"` |
| 代码块溢出 | 横向滚动容器，不撑破页面宽度 |
| 中文标题生成 slug | 用 `pinyin` 库转拼音；也可纯用 `article-<id>` 兜底 |
| 文章被大量引用 | 删除前提示，软删除可恢复 |
| 归档状态 | `ARCHIVED` 前台不显示但**返回 410**（而非 404），明确告知搜索引擎"曾存在现在没了" |

### 4.9 未来扩展

- 系列文章（`seriesId` + `seriesOrder`），支持"第 1/5 篇"
- 评论区（`allowComment` 字段已预留）
- 文章付费/订阅可见
- AI 自动生成摘要与标签建议

### 4.10 验收标准

- [ ] 发布文章后 5 秒内前台可见（验证 tag 失效链路）
- [ ] 草稿直链 404，预览链接可访问
- [ ] TOC 生成正确，滚动时高亮跟随
- [ ] slug 冲突时后台实时提示且接口返回 409
- [ ] 阅读量同 session 只计一次
- [ ] 关闭文章模块后 RSS 仍正常（只输出日志）
- [ ] 文章详情页移动端代码块可横向滚动且不撑破布局

## 模块 5 · 关于我（About）

### 5.1 定位

**整站唯一的"转化页"。** 访客看完作品和文章，最后一站都是这里 —— 所以要明确回答三个问题：**你是谁、你擅长什么、怎么联系你。**

与其他模块的关键区别：**它是单例（只有一份数据），不是列表。**

### 5.2 数据来源

| 数据 | 来源表 |
|---|---|
| 基本信息、优势、技能、社交、服务、联系 | `Profile`（单例行） |
| 工作经历 | `TimelineItem`（`type=WORK` 且 `showOnAbout=true`）★ 复用 |

接口：`GET /api/v1/profile`

### 5.3 页面区块

| 区块 | 字段 | 可关闭 |
|---|---|---|
| Hero | `name` / `headline` / `avatar` / `jobTitle` / `company` / `location` / `yearsOfExp` / `resumeUrl` | ❌ 必显示 |
| 关于我 | `bio`（Markdown） | ✅ |
| 个人优势 | `advantages[]` | ✅ |
| 技能矩阵 | `skills[]` | ✅ |
| 工作经历 | 来自 `TimelineItem` | ✅ |
| 我能提供 | `services[]` | ✅ |
| 联系我 | `email` / `phone` / `socials[]` / `contactVisible` | ✅ |

### 5.4 关键字段结构

**`advantages`（个人优势）**
```jsonc
[
  {
    "title": "工程化落地能力",
    "description": "从 0 搭建设计系统、CI/CD 与代码规范体系，覆盖 12 条业务线",
    "icon": "wrench"
  }
]
```
> 常见错误：写"学习能力强""抗压能力强"这类无法验证的形容词。后台的字段提示应给出正面示例。

**`skills`（技能矩阵）**
```jsonc
[
  {
    "category": "前端框架",
    "items": [
      { "name": "React", "level": 5, "years": 5 },
      { "name": "Vue",   "level": 3, "years": 2 }
    ]
  }
]
```
`level` 1–5 星，前台渲染为分段进度条，避免"精通/熟练"这类主观词。

**`socials`（社交链接）**
```jsonc
[
  { "platform": "github",  "label": "GitHub",  "url": "https://github.com/xxx",  "icon": "github" },
  { "platform": "juejin",  "label": "掘金",    "url": "https://juejin.cn/user/xx", "icon": "book-open" },
  { "platform": "email",   "label": "邮箱",    "url": "mailto:hi@example.com",   "icon": "mail" }
]
```

**`services`（我能提供）**
```jsonc
[
  { "title": "技术咨询", "description": "前端架构选型、性能优化方案评审", "icon": "message-circle" },
  { "title": "合作机会", "description": "接受远程/兼职的技术合作",        "icon": "handshake" }
]
```

### 5.5 前台交互

| 交互 | 行为 |
|---|---|
| Hero 下载简历 | `resumeUrl` 直链下载；未设置时按钮不渲染 |
| 联系我 | `contactVisible=false` 时只显示非mailto/tel且不含公开邮箱电话的社交链接；公共DTO、首页、页脚、metadata及JSON-LD同步过滤 |
| 技能条 | 进入视口时才有填充动画（`IntersectionObserver`），`reduced-motion` 时直接显示 |
| 工作经历 | 只显示最近 2–3 条 + 「查看完整时间轴 →」跳 `/timeline` |
| 优势卡片 | PC 3 列 / 平板 2 列 / 移动 1 列 |
| 邮箱防爬 | 邮箱用 JS 拼接输出（`data-user`/`data-domain`），避免被爬虫直接抓取明文 |
| 复制邮箱 | 点击邮箱图标复制到剪贴板 + toast「已复制」 |

### 5.6 后台管理

单例表单，区块折叠（详见 [04-admin-console.md §7](04-admin-console.md)）。

**关键设计**：「工作经历」区块在后台是**只读的**，显示：

```
▶ 工作经历（来自时间戳模块，共 3 条）              [ 去管理 → ]
  ⓘ 此处数据与「时间戳」模块共用，请在时间戳中编辑
```

这从 UI 上强化 D5 决策，防止用户在这里改了不生效而困惑。

**数组字段编辑器**（优势/技能/社交/服务共用）：拖拽排序、图标选择器、删除带撤销。

### 5.7 开关行为

| 操作 | 效果 |
|---|---|
| `enabled = false` | `/about` → 404；导航移除；**联系方式彻底不可达**（此时确保首页或页脚仍有联系方式，否则失去转化入口） |
| `config.sections.advantages = false` | 隐藏优势区块 |
| `config.sections.skills = false` | 隐藏技能区块 |
| `config.sections.experience = false` | 隐藏工作经历区块（不影响 `/timeline`） |
| `config.sections.contact = false` | 隐藏联系区块 |
| `contactVisible = false` | 区块仍在，但不显示邮箱与电话，仅留非mailto/tel且不含公开邮箱电话的社交链接；首页、页脚、metadata及公共DTO同步过滤 |
| `timeline.enabled = false` | 工作经历区块**被动隐藏**（依赖关系） |

> **依赖提示**：后台关闭 `about` 模块时，确认框要提示「关闭后全站将没有任何联系方式入口」。

### 5.8 边界与异常

| 情况 | 处理 |
|---|---|
| 首次部署 `Profile` 表为空 | 种子数据插入占位行；前台显示"待完善"提示而不崩溃 |
| `bio` 为空 | 整个「关于我」区块不渲染 |
| `skills` 数组为空 | 技能区块不渲染 |
| 头像缺失 | 用姓名首字母 + 强调色背景生成头像 |
| 简历链接失效 | 后台提供"测试链接"按钮 |
| 所有区块都关闭 | Hero 仍然显示（`name` + `headline` 是必填），页面不至于空白 |

### 5.9 未来扩展

- 访客留言板（`Message` 表 + 审核）
- 邮件订阅（`Subscriber` 表 + Resend 发信）
- 可用性状态（"目前接受合作 / 暂不接新项目"）
- 时区与当前时间显示（"杭州 · 现在是 14:23"）

### 5.10 验收标准

- [ ] 修改一条 `TimelineItem` 后，「关于我」页经历区块同步更新
- [ ] `contactVisible=false` 时全站公开DTO/HTML/RSC/metadata/JSON-LD不出现email/phone或mailto/tel
- [ ] 关闭所有区块后页面仍显示 Hero，不白屏
- [ ] 移动端技能条填充动画正常且不卡顿
- [ ] 后台经历区块显示为只读并给出跳转链接
- [ ] 关闭 `timeline` 模块后，关于我页经历区块隐藏且有合理表现

## 模块 6 · 首页（Home）— 聚合层

首页不是独立内容模块，而是**其他模块的拼装结果**。

### 6.1 拼装规则

| 区块 | 数据来源 | 显示条件 |
|---|---|---|
| Hero | `Profile` | 永远显示 |
| 精选作品 | `Project where featured=true` | `portfolio.enabled` && `portfolio.config.home.enabled` |
| 最新文章 | `Article` 按 `publishedAt DESC` | `article.enabled` && `article.config.home.enabled` |
| 最新日志 | `Log` 按 `logDate DESC` | `log.enabled` && `log.config.home.enabled` |
| 近期经历 | `TimelineItem` | `timeline.enabled` && `timeline.config.home.enabled` |

### 6.2 区块顺序与条数

由各模块的 `config.home.order`（顺序）与 `config.home.limit`（条数）控制，后台可拖拽调整，改完即时生效。

**默认顺序**：Hero → 精选作品(2) → 最新文章(3) → 最新日志(4) → 近期经历(5)

### 6.3 降级策略

| 情况 | 表现 |
|---|---|
| 某模块关闭 | 该区块整块移除，相邻区块上移，**不留空位** |
| 某模块无内容 | 不显示该区块（而不是显示空卡片） |
| 所有模块都关闭 | Hero + 社交链接 + 引导文案「网站正在建设中」 |
| 数据加载失败 | 单个区块显示轻量错误占位 + 重试，**不影响其他区块** |

|---|---|---|---|
| `home` | **不可关闭**（站点根路径） | — | — |
| `log` | `/logs*` 404；首页区块消失；sitemap/RSS 移除 | 菜单置灰但可进入 | 无 |
| `portfolio` | `/portfolio*` 404；首页精选消失 | 同上 | 无 |
| `timeline` | `/timeline` 404 | 同上 | **同时影响 `about` 的经历区块** |
| `article` | `/articles*` 404；首页区块消失；RSS 仅剩日志 | 同上 | 无 |
| `about` | `/about` 404；导航移除；全站可能失去联系方式 | 同上 | 依赖 `timeline`（经历数据） |

**通用规则**

1. 关闭 ≠ 删除。数据完整保留，可随时重新开启。
2. 关闭后对应 API 返回空数组而非报错，避免客户端崩溃。
3. 后台仍可管理已关闭模块的内容（菜单置灰 + 标记"已关闭"）。
4. 每次开关都写 `AuditLog`，可追溯。
5. 关闭操作 5 秒内可撤销。
