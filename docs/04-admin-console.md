# 04 · 后台管理系统设计

[← 上一篇：接口契约](03-api-spec.md) · [返回 README](../README.md) · [下一篇：前台信息架构 →](05-frontend-ia.md)

后台的唯一使命：**让你在不想写代码的时候，也能改站点的任何东西。**

---

## 1. 设计原则

| 原则 | 具体落地 |
|---|---|
| **零发版运维** | 改文案、开关模块、换排序、发内容，全部不触发部署 |
| **危险操作有护栏** | 关闭模块前告知影响条数；删除进回收站；彻底删除需二次确认 + 输入名称 |
| **一切可追溯** | 每个写操作落 `AuditLog`，记录 before/after 差异 |
| **列表页是主战场** | 80% 时间在列表页，优先打磨表格的筛选、批量、键盘操作 |
| **乐观更新** | 开关、排序、状态切换立即反馈，失败再回滚并提示 |
| **移动端可应急** | 后台以 PC 为主，但手机能完成"改错别字 + 发一条日志" |

**行的交互**

| 元素 | 交互 | 反馈 |
|---|---|---|
| `⋮⋮` 手柄 | 长按拖拽 | 行浮起 + 阴影，释放后立即 `PATCH /modules/reorder`；失败回滚 |
| 模块名称 | 单击变输入框 | 失焦或回车保存；`Esc` 取消 |
| 前台路径 | 单击变输入框，实时校验唯一性 | 冲突时红边框 + 提示；保存时旧路径自动 301 |
| 内容量 | 只读徽章 | 点击跳到对应模块的列表页 |
| 显示开关 | Switch，乐观更新 | 立刻翻转；同时弹出影响摘要（见下） |
| 导航开关 | Switch，乐观更新 | 同上 |
| 配置 | 打开右侧抽屉 | 抽屉内是模块专属配置 |

### 3.2 关闭模块的确认交互

**不要用简单的「确定/取消」弹窗** —— 用户不知道关掉会发生什么。改为「影响清单 + 一键撤销」：

```
┌──────────────────────────────────────────────────────┐
│  关闭「日志」模块？                                    │
├──────────────────────────────────────────────────────┤
│  将会发生：                                            │
│   ✓ 顶部导航与移动端 Tab 中移除「日志」                 │
│   ✓ 首页「最新日志」区块整块隐藏                        │
│   ✓ /logs 与所有日志详情页返回 404                     │
│   ✓ sitemap.xml 与 RSS 中移除相关条目                   │
│                                                       │
│  不会发生：                                            │
│   ✗ 不会删除任何内容（86 条将完整保留）                 │
│   ✗ 后台「日志管理」仍可正常访问                        │
│                                                       │
│            [ 取消 ]        [ 确认关闭 ]                │
└──────────────────────────────────────────────────────┘
```
关闭成功后 toast 带 **撤销** 按钮（5 秒内可一键恢复）：

```
✓ 「日志」已关闭，前台不再显示    [撤销]
```

**各模块的配置项**（键名以 [01-architecture.md §7「config 规范结构」](01-architecture.md) 为唯一权威定义）

| 模块 | 后台可调项 → 对应 config 键 |
|---|---|
| 首页 | 各区块开关与顺序、Hero 文案、是否显示最新内容 → 由各模块的 `home.*` 反向控制 |
| 日志 | 类型开关 → `types`；默认视图（列表/日历）→ `defaultView`；每页条数 → `pageSize`；栏目导语 → `intro`；空态文案 → `emptyText`；首页露出 → `home.enabled` / `home.limit` / `home.order` |
| 作品集 | 类型开关 → `types`；卡片布局（网格/列表）→ `layout`；每页条数 → `pageSize`；是否显示技术栈 → `showTechStack`；首页露出 → `home.*` |
| 时间戳 | 类型开关 → `types`；是否按年分组 → `groupByYear`；排序方向 → `direction`；首页露出 → `home.*` |
| 文章 | 每页条数 → `pageSize`；是否显示阅读量 → `showViewCount`；是否显示目录 → `showToc`；相关文章条数 → `relatedCount`；首页露出 → `home.*` |
| 关于我 | 区块开关（优势/技能/经历/联系）→ `sections`；是否公开联系方式 → `Profile.contactVisible`（不在 config 中） |

### 3.4 与前台的数据流

```
后台 PATCH /api/v1/admin/modules/log { enabled: false }
   ↓
moduleService.update()
   ├─ 校验（home 不可关闭、route 唯一）
   ├─ prisma.module.update()
   ├─ 写 AuditLog { resource:'module', resourceId:'log', before:{enabled:true}, after:{enabled:false} }
   └─ revalidateTag('module'); revalidateTag('content')
   ↓
前台下次请求（或立刻刷新）
   ├─ Header/TabBar  → 不含「日志」（读缓存的 module 列表）
   ├─ 首页           → 日志区块不渲染（feed 返回空数组）
   ├─ /logs          → layout 中 notFound() → 404 页
   ├─ /api/v1/logs   → service 兜底返回 { data: [], meta: { total: 0 } }
   └─ sitemap.xml    → 不含 /logs
```

**全链路 ≤ 5 秒生效**（ISR tag 失效是即时的，CDN 边缘节点通常 1–2 秒内刷新）。

### 3.5 内置约束（防止把自己站点弄坏）

| 约束 | 原因 |
|---|---|
| `home` 模块不可关闭 | 否则站点根路径 404 |
| `key` 不可修改 | 是代码里的路由组与 service 的绑定键 |
| `route` 不可与保留路径冲突 | 保留：`/admin` `/login` `/api` `/search` `/_next` |
| `route` 修改后旧路径保留 301 一年 | 保护已收录的 SEO 链接 |
| 关闭模块时二次确认 | 避免误触 |
| 关闭操作可撤销（5 秒） | 误操作兜底 |

### 4.2 规范细节

| 项 | 规范 |
|---|---|
| 搜索 | 300ms 防抖，写进 URL query，可刷新/分享/前进后退 |
| 筛选 | 全部写进 URL，多选用逗号分隔；「重置」一键清空 |
| 排序 | 点击表头切换升/降序，写进 URL 的 `sort` 参数 |
| 列设置 | 齿轮图标，勾选显示哪些列，存 `localStorage` |
| 分页 | 服务端分页；每页条数 10/20/50；切换后回到第 1 页 |
| 选择 | 表头全选；`Shift+点击` 范围选择；选择状态跨页保留（记 id 集合） |
| 行操作 | 常用操作直出图标（编辑），其余收进 `⋯` 菜单 |
| 危险操作 | 菜单里红色文字；需二次确认 |
| 空态 | 区分「没有任何内容」（引导新建）与「筛选无结果」（引导重置） |
| 加载态 | 表格骨架屏（保持行高一致，避免布局跳动） |
| 错误态 | 表格区域显示错误 + 重试按钮，不整页崩溃 |
| 键盘 | `J/K` 上下移动行焦点，`Enter` 打开编辑，`X` 选中，`/` 聚焦搜索框 |

**表单通用行为**

| 行为 | 说明 |
|---|---|
| **自动保存草稿** | 停止输入 3 秒后自动存 `localStorage`；每 60 秒或切走页面时静默 PATCH 到服务端（仅 DRAFT 状态） |
| **离开提示** | 有未保存改动时 `beforeunload` + 路由拦截 |
| **字段级校验** | Zod schema 同源；失焦即校验，提交时全量校验并滚动到第一个错误 |
| **slug 自动生成** | 标题输入时实时转拼音/英文 slug，用户手改过则停止自动覆盖 |
| **slug 唯一性** | 输入停止 500ms 后异步校验，冲突实时提示并给建议（`-2` 后缀） |
| **快捷键** | `Ctrl/Cmd + S` 保存，`Ctrl/Cmd + Enter` 保存并发布，`Esc` 返回列表（有改动则询问） |
| **图片粘贴上传** | 编辑器内直接 `Ctrl+V` 粘贴截图 → 自动上传 → 插入 Markdown |
| **拖拽上传** | 拖图片进编辑器即上传 |
| **错误定位** | `409 CONFLICT` 的 `details[].path` 精确标红对应字段 |

## 5. 内容编辑器

### 5.1 Tiptap 工具条

```
┌─────────────────────────────────────────────────────────────┐
│ H1 H2 H3 │ B I S ~ `code` │ • 1. ☐ │ " ❝ <> │ 🔗 🖼 📊 ▦ │ ⋯ │
└─────────────────────────────────────────────────────────────┘
```

| 分组 | 功能 |
|---|---|
| 标题 | H2 / H3 / H4（**不提供 H1**，H1 由文章标题占用，保证 SEO 层级正确） |
| 行内 | 粗体、斜体、删除线、行内代码 |
| 列表 | 无序、有序、任务列表 |
| 块 | 引用、代码块（带语言选择与 Shiki 高亮）、分割线 |
| 插入 | 链接、图片、表格、**自定义块**（提示框 / 折叠 / 视频 / 外链卡片） |
| 其他 | 撤销重做、全屏、Markdown 源码模式 |

### 5.2 自定义块（Markdown 语法扩展）

内容里常用的非标准块，用 Markdown 注释语法表达，保证纯文本可读：

```markdown
:::tip[小提示]
这里是一个提示框，支持 **Markdown**。
:::

:::warning
注意：这个 API 在 v2 中已废弃。
:::

:::details[点开看完整配置]
```json
{ "key": "value" }
```
:::

:::video[演示视频](https://cdn.example.com/demo.mp4)
:::
```

`react-markdown` 侧用自定义 `remark` 插件解析为 React 组件，未知语法降级为普通文本（**不报错、不丢内容**）。

### 5.3 为什么 Markdown 进出

```
Tiptap（编辑，所见即所得）
   ↓ tiptap-markdown 序列化
Markdown 字符串（入库、可 Git、可 diff）
   ↓ react-markdown 渲染
HTML（前台展示）
```
好处：哪天想换编辑器（MDXEditor、Obsidian、VS Code 直接编辑），数据零迁移。这也是 D6 决策的落地方式。

## 12. 三端适配策略

后台以 PC 为主，但保证移动端能完成应急任务。

| 端 | 策略 |
|---|---|
| **PC ≥ 1024px** | 左侧固定侧边栏（240px）+ 主内容区；表格完整列；右侧配置抽屉 |
| **平板 768–1023px** | 侧边栏收起为图标栏（64px），hover 展开浮层；表格隐藏次要列 |
| **移动 < 768px** | 顶部汉堡菜单（抽屉式导航）；**表格转卡片列表**；表单一列；操作区固定底部；编辑器工具条横向滚动 + 精简 |

**移动端例外处理**

- 富文本编辑器在移动端切到「Markdown 源码模式」优先（Tiptap 工具条在窄屏体验差）
- 媒体库移动端单列瀑布流
- 批量操作在移动端仅保留「删除」与「发布/下架」
- 拖拽排序在移动端用长按 + 上下箭头按钮兜底（`dnd-kit` 触屏支持）

## 15. 动效配置页（`/admin/settings/motion`）

后台唯一带**实时预览**的配置页。完整技术设计见 [08-motion-system.md](08-motion-system.md)，这里只描述交互。

### 为什么它和其它设置页不一样

其它设置页（基础信息 / SEO / 页脚）改的是文字，存完刷新前台就能看。**动效是"看不见就不知道自己在配什么"的东西** —— 一张写满 `gradient-flow` / `24s` / `blur 80px` 的表单，你无法判断它跑起来是什么样。

所以这一页必须有：

1. **实时预览窗**（右侧 sticky）—— 内嵌一个迷你首页，所有动效真实播放
2. **性能预估面板** —— 实时显示这份配置的 JS 体积、合成层数、LCP 影响
3. **危险配置确认** —— 命中性能红线时不直接阻止，而是列出后果让你决定

### 页面结构

| 区域 | 内容 |
|---|---|
| 页头 | H1「动效」+ 副标题「让站点活起来，但别拖慢它」+ `[预览前台 ↗]` `[恢复默认]` `[保存]` |
| 顶部条 | 全局强度四档（关闭/轻微/标准/丰富）+ 当前预设名 |
| 预设选择器 | 8 张卡片：极简 / 呼吸渐变 / 极光 / 光斑 / 网格 / 星空 / 粒子 / 自定义 |
| 左侧表单 | 6 个折叠区块：全局(5) / 背景动效(11) / 交互动画(7) / 入场动画(6) / 文字动效(3) / 微交互(4) / 性能与降级(5) |
| 右侧预览 | 预览窗（可切 亮色·暗色 / PC·移动）+ 性能预估卡片 + 建议提示 |

### 关键交互约定

| 交互 | 规则 |
|---|---|
| 点预设 | **立即套用到预览窗，但不自动保存**；顶部提示「已套用『极光』，尚未保存」+ [撤销] [保存] |
| 拖滑块 | 拖动过程中预览**即时**跟随（本地 state），松手后才进入"待保存"状态 |
| 手动改任一项 | `preset` 自动变为 `custom`，预设卡片高亮消失 |
| 切「移动」预览 | 按 `mobileIntensity` 渲染，**如实反映手机上的效果**（而不是缩放 PC 效果） |
| `respectReducedMotion` | 带 🔒 锁定为开，悬浮提示「这是无障碍要求，不可关闭」 |
| 性能预估值 | 超出阈值时卡片变黄/红，并给出可点击的优化建议 |
| 保存 | Zod 校验 → 交叉规则 → 有警告则弹确认框 → 写库 + `revalidateTag('setting')` + 写 AuditLog |
| 未保存离开 | 路由拦截 + 确认弹窗（与其它表单一致） |

### 性能预估的实时计算

`PerfEstimate.tsx` 按当前配置查表累加，不依赖实际运行：

```ts
const JS_COST = { particles: 12, cursorGlow: 2.5, parallax: 1.8, magnetic: 1.5, countUp: 1.2, revealFallback: 1.5 }
const COMPOSITE_LAYERS = { 'gradient-flow': 1, aurora: 3, 'blur-blob': 3, grid: 1, stars: 1, particles: 1 }

// 展示三条红线
// 1. JS 体积 ≤ 25KB（超出变红）
// 2. 合成层 ≤ 4（超出变黄）
// 3. 移动端重动效 = 0（开着就变黄，提示"移动端将自动降档"）
```

> **诚实原则**：预览窗在检测到 FPS 降级时，会显示「当前预览为降级状态：检测到低帧率」—— 让你知道**真实访客看到的是什么**，而不是只在你的高配机器上好看。

### 与「模块开关」的区别

| | 模块开关 `/admin/modules` | 动效配置 `/admin/settings/motion` |
|---|---|---|
| 控制 | **内容是否存在** | **内容如何呈现** |
| 数据 | `Module` 表 | `Setting` 表的 `motion` group |
| 影响面 | 路由、导航、sitemap、RSS | 仅视觉与交互，不影响可访问性与内容 |
| 危险度 | 高（会让页面 404） | 低（最坏情况是卡顿，且有六级降级兜底） |
| 确认交互 | 必须列影响清单 | 仅性能红线时警告 |
