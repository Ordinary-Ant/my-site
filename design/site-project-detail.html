项目亮点

  • 60fps 稳定运行，粒子与敌人全部用对象池管理，每分钟 GC 停顿从 12 次降到 0 次
  • 手写 AABB 与胶囊体碰撞检测，无任何第三方物理库，整包 gzip 后仅 34KB
  • 12 个关卡全部由 JSON 配置，策划可独立编辑并在编辑器里即时预览
  • 渲染与关卡数据完全解耦，新增一种敌人只需 40 行配置加一张精灵图

技术实现

整个游戏跑在一个 requestAnimationFrame 循环里，逻辑固定按 60Hz 步进，渲染则跟随屏幕刷新率。这样在 144Hz 的显示器上画面更顺，同时物理表现和 60Hz 设备完全一致，不会出现高刷设备跳得更高的问题。

碰撞是所有平台跳跃游戏最容易写歪的地方。我没有引入物理引擎，而是把地形切成瓦片，玩家用一个胶囊体近似：先用 AABB 做一次粗筛，只有真正重叠的瓦片才会进入精测分支，再按最小重叠轴把玩家推出去。

typescript复制
type AABB = { x: number; y: number; w: number; h: number };

/** 轴对齐包围盒相交检测：比逐像素检测快两个数量级 */
function intersects(a: AABB, b: AABB): boolean {
  return a.x < b.x + b.w && a.x + a.w > b.x &&
         a.y < b.y + b.h && a.y + a.h > b.y;
}

/** 圆角矩形玩家：先粗筛，再按最小重叠轴推出 */
function resolve(p: Body, tiles: AABB[]) {
  for (const t of tiles) {
    if (!intersects(p.box, t)) continue;  // 99% 的瓦片在这里被排除
    const overlapX = Math.min(p.box.x + p.box.w - t.x, t.x + t.w - p.box.x);
    const overlapY = Math.min(p.box.y + p.box.h - t.y, t.y + t.h - p.box.y);
    if (overlapY < overlapX) { p.vy = 0; p.box.y -= overlapY; }
    else { p.vx = 0; p.box.x -= overlapX; }
  }
}

这套写法在实测里能稳定跑满 60fps，最坏情况（满屏弹幕）下每帧的碰撞检测也不到 0.4ms。真正的开销反而在精灵图绘制上，所以后来我又加了一层脏矩形，只重绘发生变化的区域。
